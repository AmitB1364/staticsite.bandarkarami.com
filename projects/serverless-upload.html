// architecture

How a request actually flows

Six hops, three Lambda functions, zero servers to patch. The client never sends file bytes through the backend — it only ever asks for permission, then talks to S3 on its own.

  1. Users upload files through a web interface.
  2. A Lambda function generates a presigned S3 URL and returns it.
  3. The file uploads directly to S3 using that presigned URL.
  4. S3 emits an ObjectCreated event notification.
  5. The SaveMetadata Lambda reads the object's metadata and stores it in DynamoDB.
  6. The client calls GET /files to read back everything that's been uploaded.

// step 04

Lambda: GenerateUploadURL

This function never sees the file itself — it just signs a temporary PUT URL that lets the client write one specific object, for a limited window of time.

generate_upload_url.py
import json
import boto3
from botocore.client import Config

s3 = boto3.client("s3", config=Config(signature_version="s3v4"))
BUCKET = "meo-bucket-26"

def lambda_handler(event, context):
    filename = event["queryStringParameters"]["filename"]
    key = f"upload-files/{filename}"

    upload_url = s3.generate_presigned_url(
        ClientMethod="put_object",
        Params={"Bucket": BUCKET, "Key": key},
        ExpiresIn=300,
        HttpMethod="PUT",
    )

    return {
        "statusCode": 200,
        "headers": {"Access-Control-Allow-Origin": "*"},
        "body": json.dumps({"uploadURL": upload_url, "key": key}),
    }
Why 300 seconds — short-lived URLs limit the blast radius if one ever leaks in a log or a browser history.

S3 event → SaveMetadata Lambda

The bucket's ObjectCreated event is wired to a second function, which reads the object's headers straight from S3 and persists them as a row in DynamoDB.

save_metadata.py
import json, boto3, uuid
from urllib.parse import unquote_plus
from datetime import datetime

s3 = boto3.client('s3')
table = boto3.resource('dynamodb').Table('meofiles')

def lambda_handler(event, context):
    for record in event['Records']:
        bucket = record['s3']['bucket']['name']
        key = unquote_plus(record['s3']['object']['key'])
        head = s3.head_object(Bucket=bucket, Key=key)

        table.put_item(Item={
            "FieldID": str(uuid.uuid4()),
            "FileName": key.split("/")[-1],
            "Bucket": bucket,
            "ObjectKey": key,
            "FileSize": head["ContentLength"],
            "ContentType": head["ContentType"],
            "UploadDate": datetime.utcnow().isoformat(),
            "Status": "Uploaded",
        })

    return {"statusCode": 200, "body": "Metadata Saved"}
No polling — S3 invokes this function directly the moment an object lands. The permission for S3 to call Lambda is added automatically when the event notification is saved.
// step 08

Lambda: GetFiles

A read-only endpoint that scans the table and hands the frontend everything it needs to render an upload history — no separate database layer required.

get_files.py
import json, boto3
from decimal import Decimal

table = boto3.resource('dynamodb').Table('meofiles')

class DecimalEncoder(json.JSONEncoder):
    def default(self, obj):
        if isinstance(obj, Decimal):
            return int(obj)
        return super().default(obj)

def lambda_handler(event, context):
    response = table.scan()
    return {
        "statusCode": 200,
        "headers": {"Access-Control-Allow-Origin": "*"},
        "body": json.dumps(response["Items"], cls=DecimalEncoder),
    }

Exposed as GET /files on the same API Gateway, so the whole pipeline lives behind two clean endpoints: one to write, one to read.
